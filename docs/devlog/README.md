# devlog

그날 작업한 내용을 그날 적어두는 폴더다. 여기 쌓인 일지를 주차 단위로 묶어서 다듬으면 `docs/blog/`의 기술블로그 글이 된다. 블로그를 나중에 몰아서 쓰려면 기억이 안 나서, 짧게라도 매일 남기는 걸 원칙으로 한다.

## 폴더 구조

```
docs/devlog/
├── _template.md                         # 일지 양식
├── week02/                              # 프로젝트 주차별 폴더 (11/16~11/22)
│   └── 2026-11-16-requirements.md
├── week03/                              # 11/23~11/29
├── week04/                              # 11/30~12/6
└── week05/                              # 12/7~
```

## 규칙

- 파일 이름은 `YYYY-MM-DD-주제.md`. 같은 날 두 사람이 쓰면 주제 뒤에 이름을 붙인다 (`2026-11-24-agent-nayeon.md`)
- 맨 위에 그날 작업한 요구사항 ID를 적는다. 커밋, PR과 같은 ID를 쓴다
- 막혔던 것과 어떻게 풀었는지를 꼭 남긴다. 블로그에서 제일 읽히는 부분이고, 중간보고서의 "기술적 문제 및 해결 방법" 항목 재료가 된다
- AI 도움을 받은 부분과 AI 답이 틀렸던 부분도 적는다. 최종보고서 "AI 활용 방법" 항목에 그대로 쓴다
- 커밋 메시지는 `[WBS-x.x]: 12주차 개발 일지` 형식
