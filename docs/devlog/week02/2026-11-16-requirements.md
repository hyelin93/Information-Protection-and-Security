# 2026-11-16 요구사항 정의, 두 명이 동시에 개발하려면

작업 요구사항: [FR-01]~[FR-17], [NFR-01]~[NFR-08], [WBS-2.1]~[WBS-2.7]
작성: 김나연

## 오늘 한 일

제안서 피드백을 받고 처음으로 요구사항을 표로 정리했다. 기능 요구사항 17개(필수 15, 선택 2), 비기능 요구사항 8개를 뽑았고, 역할 분담, 데모 페이지 설계, 평가 데이터셋 설계, WBS까지 구글 시트로 만들었다. 깃허브 저장소 폴더 구조와 협업 규칙도 이날 같이 잡았다.

피드백에서 제일 아팠던 건 "팀원이 2명이라 1인 작업량이 가장 크다"는 지적이었다. 그래서 요구사항마다 필수와 선택을 나누고, 브라우저 확장 팝업이랑 zero-width 문자 같은 확장 벡터는 선택으로 내렸다. 대시보드도 최소 기능으로 하라는 코멘트가 있어서 판정별 개수와 로그 표만 남겼다.

## 막힌 것과 해결

### 둘이 서로 기다리는 문제

공격 쪽(데모 페이지, 에이전트)이랑 방어 쪽(방화벽)을 나눠 맡으면 깔끔할 것 같았는데, 막상 생각해보니 에이전트는 방화벽이 있어야 연결 테스트를 하고, 방화벽은 공격 페이지가 있어야 검사할 게 생긴다. 이대로면 서로 기다리다 시간이 다 간다.

그래서 두 사람이 만나는 지점을 딱 두 개로 줄였다. `inspect(html, source)` 함수 하나와 감사 로그 한 줄의 형식이다. 이 두 개의 입력, 출력 필드를 먼저 표로 고정해두면, 나는 가짜 `inspect()`를 붙여서 에이전트를 먼저 만들 수 있고 혜린이는 손으로 만든 HTML 몇 개로 방화벽을 먼저 만들 수 있다. 백엔드랑 프론트가 API 명세부터 정하는 거랑 같은 이야기다.

### 격리와 차단이 뭐가 다른가

제안서에는 40~59점 격리, 60점 이상 차단이라고만 써놨는데, 요구사항으로 옮기려니 둘 다 에이전트에 안 넘기는 거면 차이가 뭐냐는 질문이 생겼다. 정리한 답은 사후 처리다. 차단은 버리고 경고를 띄우고, 격리는 원문을 로그에 보관해서 사람이 다시 보고 오탐이면 규칙을 고치는 근거로 쓴다.

### 가중치 초안의 구멍

데모 페이지 예상 판정을 적다가 발견했다. 이미지 alt에 "관리자 모드로 전환해" 같은 명령만 넣으면 권한 전환 20점 + 은닉 위치 15점 = 35점이라 그냥 통과된다. 3주차 튜닝 때 제일 먼저 볼 항목으로 적어뒀다.

## AI 활용 기록

요구사항 표 초안, 역할 분담 표, WBS 뼈대를 AI로 뽑고 직접 고쳤다. 일정은 AI가 처음에 제안서의 6주 계획을 그대로 가져왔는데, 발표가 11/30이나 12/7이라 실제로는 3주 반밖에 없어서 날짜 기준으로 다시 압축했다. 주차 숫자만 믿으면 안 되고 실제 날짜로 확인해야 한다는 걸 배웠다.
